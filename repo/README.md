# Пилот docs-as-code: учётное ядро ЦД

Основная цепочка: UC-027, 029, 032, 033, 037, 046, 047, 056, 057 — выпуск → счёт → зачисление → сверка → выписка.

Один факт — один файл. Ссылки — `[[ID]]`, `[[ID#пункт]]` или `[[ID#пункт~текст]]`; коды в обычном тексте (R-002, K13, п.6.2, OD-22…) сборка превращает в ссылки сама.

| Папка | Что хранит | Формат |
|---|---|---|
| norms/ | выжимки норм: конкретные требования с пунктом, редакцией и датой сверки | Markdown + YAML-шапка |
| rules/ | правила: суть → как применяется → поля → пример; в шапке — нормы (`sources`), статус, сценарии (`applies_to`) и происхождение из пакета (`origin`) | Markdown + YAML-шапка |
| decisions/ | решения: что, почему, дата, что порождает | Markdown + YAML-шапка |
| questions/ | открытые вопросы: что решить, кто решает, что действует до решения; закрытые — со ссылкой на решение | Markdown + YAML-шапка |
| model/ | сущности и поля; у поля `trace` — норма или правило | YAML |
| config/ | настройки ядра (справочники); файл загружается в систему как есть | YAML |
| arch/ | архитектура и интерфейсы (том 05): ARCH, COMMANDS, IF-01…06, FORM-0xx, BR-NFR-xx | Markdown + YAML-шапка |
| guide/ | справочные разделы томов 01, 02, 03, 04, 06: границы, типы, связи, переходы STATE-UC-0xx, протокол приёмки | Markdown + YAML-шапка |
| usecases/ | сценарии: самодостаточный текст со ссылками | Markdown + YAML-шапка |
| acceptance/ | проверки «Дано / Когда / Тогда»; теги связывают с правилами и нормами | Gherkin |

**Перенесено как есть.** Файлы со статусом «перенесено как есть» взяты из томов без правки; в шапке `review` — замечания предварительного ревью. Ревью по мере работы: правим текст, убираем `review`, ставим статус.

**Статусы правил:** `действует` — работает в ядре; `выключено в CD-D-10` — правило верное, операция выключена в матрице; `вне ядра` — делает другой компонент; `цель — профиль РЦД`.

Сборка: `python build.py` → `site/index.html`. Сборка проверяет, что каждая ссылка ведёт в существующий файл и пункт.
Зависимости: Python 3, `pyyaml`, `markdown`.
