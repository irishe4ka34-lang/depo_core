Решения по [[UC-046]]:

1. **Режимы.** Э1 — документ ОИС, зарегистрированный операционистом; цель — API (у РЦД — опрос статуса).
2. **Классы сообщений ([[OD-22]]).** Квитанция — доставка; статус — ход исполнения; подтверждение — финальность и основание для учёта ([[NR-892-11#11.1]]). Аналоги ISO 20022: `admi.007`, `sese.024`, `sese.025`. Обязательные поля и проверка подлинности — в [[UC-046]].
3. **Ключи ([[MODEL-Q03]]).** Сообщения — «источник + eventId» (Э1 — хэш файла); эффекта — «ОИС + ID операции ОИС + вид эффекта» ([[C07]]); нашего запроса — `request_key`. Все бессрочные.
4. **Порядок версий.** Обрабатывается только следующая по номеру; меньший номер статус не меняет; пропуск ждёт до конца рабочего дня, затем запрос текущего статуса, который закрывает пропуск.
5. **Квитанции.** Квитанции ОИС нам — в K21 при нашей операции K11, исполнением не являются. Наши квитанции ОИС — рубильник `send_receipts` в CD-D-27; в Э1 выключен.
