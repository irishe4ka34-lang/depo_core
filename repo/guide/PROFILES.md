Статусы источников и открытые решения — КЭ1-01

CD-D-09 классифицирует право; K03 хранит конкретный выпуск и его версию. Ни название профиля, ни решение о выпуске сами по себе не создают позицию. Одно решение не следует без проверки отождествлять с одним активом. Следующие поля — логический состав для ревью, не предписание SQL и не миграция модели Э1.

Общий состав реестра по NR-01, пункты 3.7–3.11: вид цифрового права (ЦФА/УЦП/ГЦП), виды удостоверяемых прав, эмитент, уникальный ID актива, наименование и ИНН ОИС. Статус — Н в тексте 892-П, пока на регистрации. Для конкретного выпуска сохраняются решение и версия, проверенные реквизиты, источник и доказательства ручного UC-027. Единица, точность, ограничения и внешние коды требуют данных выпуска и согласования.

Обозначение обязательности в следующей таблице: О — предлагается требовать для выбранного профиля до его допуска; У — заполняется при наличии соответствующего условия в решении. Это П на основе NR-05/06, а не подтверждение наличия фактических значений. Нет данных — OPEN, а не значение по умолчанию.

|---|---|---|

До поставки не предполагаются автоматически голосование и доходы по базовым ЦБ. |

1.4 · Решение 21.10.2026. Колонки О и У переводятся в правила обязательности CD-D-09 (REV-R13). Составляющие PF2 и отдельные денежные права PF3/PF4 хранятся в K23; объём ядра включает исполнение по каждой составляющей (REV-R14).

Для PF3/PF4 применяются ограничения статьи 8 части 3: акции и конвертируемые в акции эмиссионные бумаги — только непубличных АО; эмиссия базовых бумаг регулируется 39-ФЗ. Решение адресуется определённому кругу лиц в случаях статьи 7 части 13. Квалификационные и иные ограничения получателя проверяются по применимому режиму и выпуску; не назначаются одинаковыми для всех профилей.

NR-01 п.8.2 задаёт учёт в штуках, п.8.3 — нижнюю границу дробной части относительно допустимого значения во внешней системе. Это известное требование текста на регистрации; оно не задаёт код unit_code ОИС, scale и округление конкретного выпуска. Фактические настройки и применимость режима остаются OPEN.

CD-D-09 — четыре кандидатные строки. PF1–PF4 служат только локальными ссылками. Общие для каждой строки незаполненные поля: external_type_status_ref = OPEN, mapping_rule_version = OPEN, unit_code = OPEN, precision_rule = OPEN. Подстановка «штука», scale или кода ОИС запрещена без фактуры. allowed_operation_refs ниже — ссылки на условную матрицу, не список уже разрешённых команд.

| Локальный ID / right_kind | allowed_operation_refs | Статус и уточнение |
|---|---|---|
| PF1 / Денежные требования | MX01–MX08; MX09 при наличии выплат; MX12 по применимому основанию | П; фактические значения и специальный долговой режим OPEN. |
| PF2 / Денежные требования и иные права | MX01–MX08; MX09–MX12 по составу частей | П; категория ЦФА/ГЦП и конкретные составляющие требуют уточнения выпуска. |
| PF3 / Осуществление прав по ЦБ | MX01–MX08; MX09 при выплатах; MX10; MX12 | П; объём прав, базовые ЦБ и цепочка инструкций OPEN до решения/контрактов. |
