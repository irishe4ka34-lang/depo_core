Дополнение CD-D-08 по NR-01, приложение, страницы 52–55. Это схема учётных счетов цифрового учёта, не бухгалтерский план счетов. Коды ниже взяты из опубликованного текста 892-П на регистрации, а включение конкретного вида в продукт — отдельное решение. Старые обозначения NH/FNH/FAH/FNTA/TTAH/AUP и четырёхразрядное поле вида из июльского проекта не используются для новой настройки; исторические данные не переименовываются без карты миграции.

| Коды из приложения | Назначение | Статус включения |
|---|---|---|
| O; T | Обладатель; доверительный управляющий | Кандидатный старт: O; T только при сценарии ДУ. Выбор поставки OPEN. |
| N; FN; FH | Номинальный держатель; иностранный НД; иностранный уполномоченный держатель | Условно: обслуживаемая роль и правовое основание. Наш внешний N не является внутренним клиентским N. |
| OTA; TTA; NTA; FNHT; FHTA | Торговые счета обладателя, ДУ, НД, иностранного НД, иностранного уполномоченного держателя соответственно | Торговый сценарий: п.9.4 для расчётного ЦД (клиринговая организация и её согласие) либо п.9.5 для нерасчётного; не старт по умолчанию. |
| CPA; CA | Комиссионные выплаты; клиринговый счёт | По отдельным процессам выплат/клиринга. |
| OSA; TSA; NHSA; FNHSA; FAHSA | Субсчета к клиринговому: обладателя, ДУ, НД, иностранного НД, иностранного уполномоченного держателя | Только соответствующий клиринговый сценарий. |
| TA; OTSA; TTSA | Транзитный счёт; его субсчета обладателя и ДУ | Условно по транзитному процессу. |
| DA | Депозитный счёт | Условно при соответствующем основании. |
| XY | Неустановленные лица | П.11.18: нет основания зачислить на иной пассивный счёт; не обычный клиентский счёт. |
| NCA | Клиенты номинальных держателей | П.9.13: специальный случай прекращения деятельности нижнего ЦД и отсутствия иных оснований зачисления; не обычный омнибус. |
| XX | Неустановленные активы | П.9.14: непринятые к учёту цифровые валюты и иностранные цифровые инструменты на адресе ЦД; не карантин неизвестного ЦФА и не обязательный MVP. |
| AA | Активный счёт активов | Для стартового российского маршрута: п.10.1, на каждый собственный внешний N; выбранное место. |
| SA | Активный обеспечительный счёт | П.10.4: на каждый подтверждённый внешний торговый N/субсчёт N к клиринговому; не старт по умолчанию. |

Специальные случаи: по п.11.19 переход с XX допускается только на XY после решения принять актив к учёту. Вывод с XY зависит от оснований пп.11.20–11.23; универсальный автоматический возврат через месяц не задан. Отдельный код вида лица для специальных безличных счетов в приложении не определён — не подставлять произвольный 0/1/2.

В таблице перечислены все 24 пассивных вида и 2 активных вида приложения, но не утверждена необходимость открыть их все. Номер — 20 разрядов. Пассивный: 1–5 код вида с дополнением X справа; 6–8 страна по ОКСМ, с предусмотренными приложением специальными кодами; 9 вид лица (0 ФЛ, 1 ИП, 2 ЮЛ); 10–20 уникальная цифровая часть по условиям деятельности. Для NCA/XY/XX/CPA страна 000; международная организация 998; международные компании — 995/996 в установленных случаях; неизвестная страна 999. Это правила текста приложения, не созданные реальные номера.

За пределами стартовых российских маршрутов AA02/AA03: п.10.2 регулирует счёт в иностранной организации; п.10.3 предусматривает один AA на все адреса ЦД в одной иностранной ИС. Это условные целевые варианты, не отдельные подключения Э1.

AA: 1–2 = AA; 3–4 = 00 верхний ЦД, 01 ОИС, 02 иностранный ЦД, 03 иностранная ИС; 5–20 уникальная цифровая часть. SA: 1–2 = SA; разряд 3 = 0 при корреспонденции торговому N, 1 — субсчёту N к клиринговому; разряд 4 = 0 верхний ЦД, 1 ОИС; 5–20 уникальная цифровая часть. Для SA нельзя применять смысл пары 3–4 из AA. Способ присвоения уникальной части и миграция — REV-Q4.

| Подключение | Наш внутренний учёт | Внешняя сторона |
|---|---|---|
| Прямое к ОИС | O клиентов, условно T; AA с префиксом AA01 на соответствующий внешний N | Наш N открыт в ОИС. Источник внешнего подтверждения — ОИС. |
| Через верхний ЦД | O клиентов, условно T; AA с префиксом AA00 на соответствующий внешний N | Наш N открыт у верхнего ЦД. Его дальнейший счёт в ОИС не становится нашим прямым внешним N. |
| Мы обслуживаем нижний ЦД | Внутренний N для этого депонента только при отдельном сценарии | Это иная роль, чем собственный N, открытый нами наверху. Отдельный специальный «план нижнего ЦД» не требуется. |
| Через верхний ЦД, клиенты посредников (1.4) | O клиентов с обслуживающим посредником и (или) N посредника; AA00 на каждый раздел нашего N у РЦД | Наш N открыт у РЦД; РЦД подтверждает остаток нашего N. Клиенты внутри N посредника в нашем учёте не ведутся |

Привязка к текущей модели — предложение: K05 хранит клиентский счёт и тип/режим; K04 — проверенную внешнюю связь с N и верхним участником; K08 — внутренние записи; K12 — независимый внешний срез. Представление внутреннего покрытия сопоставляется с AA, но физический реестр/ключ AA и миграция модели остаются OPEN. Смысловая схема не доказывает уже реализованную регуляторную модель.
