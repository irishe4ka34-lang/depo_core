Названия относятся к объекту конкретного UC; это проектные состояния, не утверждённые технические коды. Условия ветвления — КЭ1-02 § UC-032. Несколько исходов требуют критерия выбора; произвольный выбор запрещён. В UC-032 передача заявки и получение результата выполняются вручную. Названия ниже отражают зарегистрированные факты, не стадии API; точные статусы и обязательность независимого контроля OPEN. Историческая А3 включена в основной ручной путь.

| Участок сценария | Переход или результат |
|---|---|
| Шаг 1 | Нет → Заявка подготовлена |
| Шаг 2 | Подготовлена → Проверены предусмотренные основания и полномочия; отдельное согласование и точный статус OPEN. |
| Шаг 3 | Подготовлена → Передана вручную; приём ОИС отражается только при наличии подтверждения. Канал передачи и доказательство приёма OPEN. |
| Шаг 4 | Ожидание результата → Подтверждено открытие в ОИС; только по проверяемому результату, не по факту передачи. |
| Шаг 5 | Подтверждено открытие в ОИС → Реквизиты сохранены → Ожидает привязки UC-033; готовность и позиции не создаются. |
| А1, шаг 2 | Заявка подготовлена → Счёт обнаружен → Ожидает привязки UC-033. |
| А2, шаг 4 | Получен отказ ОИС → Отказ сохранён с причиной; исправленная заявка не заменяет историю. Порядок повторного обращения OPEN. |
| А3 прежней редакции — основной ручной путь | Подготовлена → Передана вручную → Получен проверяемый результат → Ожидает привязки. Точные статусы и доказательства OPEN; не будущая автоматизация. |
| А4, шаг 2 | Заявка подготовлена → Ожидает правового решения. |
| И1, шаг 3 | Результат ручного обращения неизвестен → Ожидает выяснения; повторное открытие и готовность не подтверждаются. Способ выяснения OPEN, автоматический запрос статуса по requestId не задан. |
| И2, шаг 4 | Принята ОИС → Расхождение; не связывать с активом до решения. |
| И3, шаг 5 | Повтор того же подтверждённого результата не создаёт новую запись счёта; неподтверждённые сведения → Ожидает подтверждения, готовность UC-033 не устанавливается. API-квитанция не требуется. |
