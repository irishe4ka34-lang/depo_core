| Тип | Общее правило и открытые параметры |
|---|---|
| ID | Непрозрачный идентификатор; формат, длина и генератор OPEN. Различать requestId, orderId, внешний operationId, entryId, caseId, eventId, paymentId и clientId IAM. Внешний ID хранить с пространством источника; область уникальности и срок дедупликации выбираются отдельно. |
| Количество права | Точное decimal с выпуском, единицей и местом учёта. Представление и точность — строка «Количество: представление и точность» (решение 21.10.2026). Не применять двоичный float по умолчанию. Доступное количество не отрицательно; 10 в примерах — количество, не сумма денег. |
| Момент и период | Различать действие, внешнее событие, получение и исторический срез. Предложение — UTC с исходной зоной/offset; неизвестную зону не придумывать. Границы периода, clock skew, effective/recorded time и поздние события — MODEL-Q05. |
| Порядковый номер | Логическая граница фиксации для порядка при равном timestamp; это не выбранный механизм sequence СУБД. |
| Версия и профиль | Неизменяемое содержание с непрозрачной версией. Условия, договоры, правила, данные, расчёты и сообщения воспроизводимы. Пересечения периодов и задние исправления OPEN. Профили/CD-D — проверяемые мастер-данные, не FK к неописанной таблице. |
| Структурированный снимок | Сохраняемое значение с проверяемыми форматом и версией профиля; не произвольный невалидируемый JSON. |
| Документ и подпись | Связывать оригинал, хэш, подписанта, проверку и источник с действием. Алгоритм, контейнер, хранение отзыва/времени и retention/hold OPEN. |
| Состояние | Отдельная машина состояний каждого объекта; общего enum нет. Полные guards и переходы требуют нормализации; основной каталог — КЭ1-04 § STATES. |
| Деньги | В цепочке Э1 нет выплат. Для будущей денежной модели нужны сумма, валюта, версия расчёта, получатель, paymentId и банковский исход; точность, налоги, частичное покрытие и распределение возвратов OPEN. Количество права не является деньгами. |
| Количество ЦВ (1.4) | Хранится точно в минимальных единицах актива, не менее 30 десятичных знаков целой части (API РЦД: amount.value — строка [1;30]). Пересчёт из титульной единицы — по title_factor версии актива, без округления. Пример: 6×10^20 минимальных единиц ETH не помещается в 64-битное целое. Требование к типу данных действует и для Э1 (I15). |
| Количество: представление и точность (1.4) | Решение 21.10.2026. Хранится целым числом минимальных единиц выпуска, тип не уже NUMERIC(38,0) — запас к 30 знакам API РЦД. Значение для человека = units / 10^scale. scale задаётся у каждой версии выпуска в K03 (0–18): для ЦФА — из решения о выпуске, для ЦВ — amountPrecision РЦД; по умолчанию не подставляется, без него проведение запрещено. Учёт не округляет: количество, не кратное минимальному шагу выпуска, отклоняется. Округление допустимо только в расчёте выплат по формуле решения о выпуске. Двоичный float запрещён. Ориентиры: ЦФА на практике — целые штуки, scale 0 (решение о выпуске ЦФА Сбера: «дробление ЦФА менее 1 шт. не допускается»); BTC — 8; токены Ethereum — до 18 (EIP-20: целые uint256 и decimals токена); паи ПИФ — не менее 5 знаков (Приказ ФСФР 13-65/пз-н, п.3.3); 892-П п.8.3 — дробная часть не мельче, чем во внешней системе. Правило — КЭ1-04 REV-R12. |

Общие обозначения проверок в карточках полей: G1 — проверить формат и применимость; G2 — FK ведёт на существующую неизменяемую запись или закреплённую версию; G3 — внутренний ID создаётся генератором ЦД, неизменен и уникален в сущности, не является внешним ID. Обычный источник заполнения — ЦД (предложение); иной источник явно указан в карточке. Все примеры условные. Эти сокращения не отменяют отдельные условия полей.
