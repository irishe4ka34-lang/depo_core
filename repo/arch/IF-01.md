В Э1 сотрудник работает с реальными заявлением и результатом; реальное открытие не выполняется. IF-01 — граница сведений ручного UC-032, не API. Реальный канал, средство подписи, доказательства и контроль OPEN.

Связи: CD-UC-032, CD-UC-033

Владелец факта: ОИС владеет фактом открытия, accountId, реквизитами и статусом внешнего счёта. ЦД владеет своей заявкой и версионированной связью с местом учёта/активом.

| Поле / группа | Источник | Условие |
|---|---|---|
| Внутренний ID регистрации заявки; внешний номер обращения только при его наличии в полученном материале | SRC-014 P00464/P00474/P00503/P00539 | Внутренний ключ не объявлен requestId ОИС или обязательным correlation ID обмена. Реальные идентификаторы и порядок сопоставления OPEN. |
| Назначение счёта; подтип НД ЦД; регистрационные сведения ЦД; заявленная роль; представитель; подпись | SRC-014 P00463/P00474/P00527–00529 | По применимому основанию и полученным документам; ручное оформление не означает автоматическую ЭП ядром. Обязательность/формат OPEN. |
| Основание: версия правил, результат проверки, документ и версия только при применимости | SRC-014 P00530–00531 | По указанному сценарию; транспортное имя/тип OPEN |
| Ответ: accountId и номер счёта, подтип, статус, момент открытия, исход/причина отказа, версия реквизитов | SRC-014 P00465/P00490/P00520/P00539 | Сотрудник сохраняет по проверяемому результату; не обязательный ответ API. Формат и доказательства OPEN. |
| S42/message ID — исторические поля интеграционного варианта, не обязательные реквизиты ручного UC-032 | SRC-014 P00540 | Не генерировать для ручного пути. Для других интеграций требования к версиям/ID сохраняются по их собственным контрактам. |
| Связь ОИС — внешний счёт — место учёта — актив/область активов и версия | SRC-022 P03042–03049 | Внутренний объект ЦД; не заявляется обязательным payload ОИС |

Повторная регистрация того же результата не создаёт вторую карточку внешнего счёта. Отсутствие результата ручного обращения не доказывает отказ и не разрешает повторное открытие. Алгоритм поведения ОИС по повторному requestId этим UC не задаётся.

Открытие не создаёт движение цифровых прав; подтверждение реквизитов не увеличивает актив или пассив ЦД.

Передача заявки, получение результата открытия и готовность связи UC-033 различаются. Непроверенные или противоречивые сведения не подтверждают открытие; API ACK и автоматический деловой ответ не требуются.

Полномочие и правовое основание проверяются; отсутствие подтверждения не равно отказу ОИС. Отдельный контролёр, способ проверки и достаточность доказательств остаются OPEN.

OIS-OD-05/15: обязательные документы, срок ответа, допустимость второго счёта и дополнительного назначения

CD:OD-13: вид/режим счёта и юридическое основание. SRC-022 P02959 говорит о договорном основании; SRC-014 P00478 прямо исключает универсальную обязательность отдельного договора — согласовать применимость, не навязывать договор всем случаям.

Гонка двух заявок на одно назначение и параллельное изменение реквизитов: согласовать уникальность/версионность, не открывать второй счёт автоматически

Источники прежней модели: SRC-014 P00459–00541; SRC-022 P02955–03049. Автоматический путь не действует для ручного UC-032 редакции 1.3; названия источников сохраняют происхождение. Остальные интерфейсы не отменены.

1.4 · Профиль РЦД — цель. РЦД: открытие счёта и разделов — вне API, по договору; API только читает счета и разделы (1.3–1.4).
