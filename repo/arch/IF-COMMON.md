IF-01–06 — смысловые границы, промышленный статус NOT_READY. Для Э1 применяется профиль ручного обмена из настроек. Транспортные имена, типы, длины, схемы, поля подписи, коды ошибок и численные интервалы не выбираются по названию интерфейса.

Общие открытые параметры: CD:OD-22 / OIS-OD-06; профиль S42, контрагент, направления, версии и сроки действия; область и срок уникальности ID, нормализация/хэш, конфликт, архив и миграция; повторы, порядок, восстановление пропусков; механизм конкуренции; двусторонние схемы, подпись, адресация, квитанции и финальность. Определение механизма не отменяет известные инварианты. ОИС владеет внешним фактом, ЦД — собственным учётным результатом. Для UC-027 автоматический контракт получения выпуска, извлечение реквизитов, проверка ЭП ядром и отправка квитанции ОИС не требуются; ручное получение комплекта не конкретизирует канал передачи сотрудником ОИС. Для UC-032 выбран ручной порядок открытия: автоматическая передача заявки, подпись системой, квитанции API и автоматический опрос результата не обязательны. Иные интеграции UC-037/040/046/047 и их требования сохраняются.

Внешняя операция ОИС не является частью открытия внутреннего счёта. Результат не создаёт запись об остатке ОИС. Зависимости ЦД: действующий договор UC-008, одобренный онбординг UC-005, полномочия и модель OD-13. Без решения OD-13 допускается только аналитический черновик. Опора P02704; P02706; P02745–P02746.

В UC-032 сотрудник вручную оформляет и передаёт заявку и получает результат ОИС. ЦД хранит сведения о заявке и проверяемом результате: внешний ID, реквизиты, вид/режим, статус и происхождение. Передача не доказывает открытие. Способ передачи/получения, средство подписи, доказательства и отдельный контроль остаются OPEN; API, техническая квитанция и автоматический опрос не заданы. Внутренние проверки и экраны ОИС не описываются.

SRC-022:P02977–P02985; P02994; P03000; P03017 — происхождение прежней спецификации. Её автоматический путь заменён ручным UC-032 в редакции 1.3.

ОИС предоставляет проверяемые реквизиты, действующий статус и подтверждённую начальную позицию на точный момент. ЦД проверяет совместимость и строит свою связь. Если ОИС меняет статус или реквизиты, готовность приостанавливается до повторной проверки. Поддержка нескольких выпусков на одном внешнем счёте возможна только по утверждённой модели; для каждого актива сохраняется отдельная проверка. Опора P03046; P03060–P03068; P03084–P03091; P03128. Эта проверка UC-033 не создаёт позиции. При необъяснённом ненулевом остатке или расхождении сохраняются причина и доказательства для выяснения основания существующих записей; ввод начальных остатков требует отдельного решения.

Внешний вход содержит operationId, выпуск, счёт НД самого ЦД, количество, получателя или основание, финальный статус и время. ЦД проверяет источник и версию и отдельно подтверждает изменение позиции на согласованном срезе. Сообщение по другому счёту или моменту не зачисляется клиенту. Внутренние маршруты и экраны ОИС не входят в эту спецификацию. Опора P03407; P03415; P03438–P03439; P03482.

Внешний вход — подтверждённый остаток по счёту НД самого ЦД с идентификацией выпуска, области, момента и источника. ЦД должен проверить финальность и сопоставимость с внутренними данными. Файл с другой датой не является заменой требуемого среза. Наличие локальных внутренних величин не позволяет завершить сверку без обязательного внешнего источника. Внутренние процессы формирования внешнего остатка не описываются; контракт должен определить достаточные реквизиты и доказательства результата.

Опора P04317; P04331; P04335; P04373–P04374; P04406.

Прямой запрос внешней операции ОИС для выдачи этой выписки не определён. Источник — собственная история ЦД. Если арифметика не сходится или история неполна, выдача останавливается и открывается исключение UC-048; внешний остаток не подставляется вместо внутренней истории. Резервная выдача сотрудником возможна только по утверждённому регламенту и проверенному запросу с тем же аудитом. Опора P05083; P05103–P05111; P05126–P05127; P05137–P05138.

ЦД запрашивает факт по устойчивому ID. Ожидаемый внешний результат включает проверяемый источник и версию ответа, финальность, связь с первоначальной командой и достаточную информацию об изменении внешней позиции. Предварительный ответ, недоступность и недостаточно определённое «не найдено» не переводятся в отказ. При противоречии ЦД требует подтверждённый срез или выписку. Периодичность запроса, источник авторитетного ответа и коды реального интерфейса остаются предметом OD-22.

Опора P03689–P03693; P03712; P03715; P03726–P03727; P03756.

Внешние факты для урегулирования — подтверждённый результат исправления и новый достоверный срез. ЦД сохраняет старую и новую версии и связывает их с действием плана. Если исход внешнего исправления неизвестен, используется UC-040; повторная команда не заменяет установление факта. Внешний ответ не закрывает кейс автоматически: ЦД сопоставляет три величины, независимо проверяет результат и фактический пересмотр связанных ограничений.

Опора P04519; P04523–P04535; P04547–P04548; P04561–P04565.

1.4 · Профиль РЦД — цель. Профиль РЦД опирается на реальный документ API (изменения от 30.09.2026), но остаётся NOT_READY: нет контракта повтора, отчёты и подписанные подтверждения объявлены будущими.

1.4 · Решение 21.10.2026. Адаптер РЦД — справочник активов. Адаптер периодически и по требованию вызывает метод 1.1, сохраняет снимок с protocolVersion и сопоставляет активы с версиями K03 по network + symbol (при наличии — symbolISO/networkISO). Количество на входе и выходе — строка целых минимальных единиц (amount.value); перевод в учётные единицы — без округления (REV-R12). Изменение разрядности или единицы у используемого актива не применяется автоматически (REV-R16). Код актива заранее в адаптер не вносится.
