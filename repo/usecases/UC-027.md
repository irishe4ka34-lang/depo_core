## Цель
Завести в реестр активов ЦД карточку выпуска ЦФА с реквизитами, которых требует 892-П, чтобы по выпуску можно было открывать позиции и проводить операции. Регистрация выпуска сама по себе позиций не создаёт.

## Предусловия

- У операциониста есть полномочие на регистрацию выпусков.
- В настройках есть профили прав и правила обязательности ([[CFG-CD-D-09]]) и матрица допустимых операций по профилям ([[CFG-CD-D-10]]).
- Обмена с ОИС нет: решение о выпуске и ЭП получают вручную ([[REV-R16]]).

## Основной порядок

### Шаг 1. Операционист получает решение о выпуске
Скачивает решение о выпуске с ЭП с сайта оператора ИС (Мастерчейн) или получает от сотрудника ОИС. Документ регистрируется с номером, датой и временем ([[NR-892-9#1.12]]).

### Шаг 2. Операционист проверяет подпись и документ
Проверяет ЭП и сам документ. Ядро ЭП не проверяет; результат проверки сохраняется как доказательство вместе с документом ([[NR-892-3#3.13]]). При отрицательном или незавершённом результате регистрация невозможна (И1).

### Шаг 3. Операционист вводит реквизиты
По решению вручную вводит:

- вид цифровых прав — ЦФА, УЦП или ГЦП — и виды удостоверяемых прав ([[NR-892-3#3.7]]);
- профиль права PF1–PF4 и реквизиты этого профиля: для денежного требования — валюта, сумма или формула, сроки, обязанное лицо ([[NR-282-7#profiles]]);
- эмитента и оператора ИС с наименованием и ИНН ([[NR-892-3#3.11]]);
- уникальный идентификатор по 892-П: номер решения о выпуске, при необходимости — с идентификаторами прав через `_` ([[NR-892-3#3.10]]);
- число знаков после запятой и минимальный шаг количества; для ЦФА обычно 0 и 1 ([[REV-R12]]);
- если прав в выпуске несколько — каждую составляющую отдельно ([[REV-R14]]).

Отсутствующие данные не выдумываются: поле остаётся пустым, и это покажет шаг 4.

### Шаг 4. Система проверяет карточку

- обязательность реквизитов по правилам профиля: исход PASS, MISSING с перечнем полей или UNDETERMINED ([[REV-R13]]);
- точность: число знаков 0–18 и не мельче допустимого во внешней системе ([[NR-892-8#8.2]]);
- уникальность пары «ОИС + ID выпуска» и уникального идентификатора по п.3.10;
- версию и допустимый статус выпуска;
- допустимые операции выпуска — строки матрицы для его профиля права ([[CFG-CD-D-10]]): например, для PF1 доступны зачисление, списание, переводы, обременения и погашение, а выплаты — только если они предусмотрены решением; незаданные сочетания не разрешены.

Конфликт с существующей карточкой её не перезаписывает.

### Шаг 5. Операционист подтверждает регистрацию
При исходе PASS карточка переходит в `MAPPED` и становится доступной для учётных сценариев — в пределах строк матрицы, включённых для Э1 ([[CFG-CD-D-10]]). Результат проверки и версия правил сохраняются ([[REV-R13]]).

### Шаг 6. Аудит
Сохраняются сотрудник, время, введённые сведения и версия, исход проверки и ссылка на решение о выпуске.

## Альтернативные ветви

- **А1, шаги 4–5. Повтор.** Та же команда с теми же данными возвращает прежнюю карточку, второй не создаёт.
- **А2, шаг 4. Не хватает реквизитов.** Исход MISSING или UNDETERMINED → карточка в `NEEDS_REVIEW`, операции по ней недоступны; операционист дополняет данные ([[REV-R13]]).
- **А3. Новая версия выпуска.** Новые сведения о версии или статусе не меняют карточку автоматически: создаётся новая версия в `NEEDS_REVIEW` и дело ([[REV-R16]]).
- **А4, шаг 3. Составное право (PF2).** Вводятся не менее двух составляющих и способ их сочетания; для `ALTERNATIVE` — порядок выбора ([[REV-R14]]).

## Ошибки и неопределённые результаты

- **И1, шаги 1–2.** Нет решения или ЭП, документ некорректен, проверка отрицательна или не завершена → регистрации нет.
- **И2, шаг 4.** Конфликт идентификатора или версии → разбор без перезаписи и без дубля.
- **И3, шаг 5.** Тайм-аут после записи → исход выясняется по ключу команды, повтор возвращает сохранённый результат.
- **И4, шаг 4.** Число знаков мельче допустимого во внешней системе или не задано → отказ с причиной ([[REV-R12]]).
