## Цель
После [[UC-032]] у нас есть счёт N у ОИС и счёт активов AA, но ЦД ещё не знает, какие выпуски будут учитываться через этот счёт. UC-033 создаёт запись «выпуск X учитывается на нашем счёте N у оператора Y» — это и есть **связь [[K04]] (место учёта выпуска)**. Без неё ЦД не может принять зачисление этого выпуска: непонятно, на какой AA писать покрытие и с каким остатком у ОИС сверяться.

Прежде чем разрешить операции, UC-033 подтверждает, что учёт на трёх уровнях сходится.

**Три уровня учёта** ([[REV-R2]], [[I01]]):
- **обязательства** — позиции депонентов на пассивных счетах, которые ведёт ЦД: O, T, счета N посредников-ЦД;
- **активы** — внутреннее покрытие ЦД на счёте активов AA ([[NR-892-APP#active]]), открытом в UC-032 на этот счёт N ([[NR-892-10#10.2]]);
- **внешние** — подтверждённый остаток на нашем счёте N у ОИС.

Это одно и то же количество, учтённое на разных уровнях: 60 у клиента А + 40 у клиента Б = 100 на AA = 100 на N. Складывать уровни нельзя. По 892-П сумма на активных счетах равна сумме на цифровых ([[NR-892-8#8.6]]).

## Предусловия
- В UC-032 счёт N открыт и подтверждён уведомлением оператора; счёт активов AA открыт.
- Выпуск зарегистрирован ([[UC-027]]).
- В матрице CD-D-10 для профиля права выпуска включено зачисление (MX01 или MX04) — иначе А3.

## Основной порядок

### Шаг 1. Операционист выбирает счёт и выпуск
На форме ЭФ-33 выбирает счёт N из UC-032 и карточку выпуска из UC-027.

### Шаг 2. Система проверяет и создаёт связь
- **Счёт N можно использовать.** Его последнее состояние, зарегистрированное в ЦД по документам ОИС, — «открыт»: открытие подтверждено уведомлением в UC-032, и после этого не регистрировались приостановление или закрытие. Сам ЦД состояние счёта у ОИС не видит — только то, что внесено по документам.
- **Нет конфликта.** У выпуска нет действующей связи, которая противоречит новой ([[C12~примеры конфликтующих связей]]). Конфликт — И1.
- **Создаётся связь** K04 «выпуск ↔ счёт N у оператора» в состоянии `UNVERIFIED`: зачисления по ней ещё запрещены.

Связь не переписывается. Первая привязка — версия 1. Если позже у счёта изменились реквизиты или связь перепривязали, создаётся версия 2, а версия 1 помечается заменённой. Операции, проведённые при версии 1, продолжают ссылаться на неё, поэтому любую старую выписку и сверку можно воспроизвести ([[STATES#custody_link]]).

### Шаг 3. Операционист получает выписку ОИС и регистрирует её
Источник внешнего остатка — электронная выписка (справка) оператора о количестве на нашем счёте N, подписанная УКЭП; тот же вид документа, что и для ежедневной сверки ([[NR-892-6#6.1]], [[DEC-2026-10-22-02]]).

- **Новый счёт, по нему ещё не было операций.** Отдельный запрос не нужен: уведомление об открытии из UC-032 подтверждает ноль на момент открытия.
- **К счёту привязывается ещё один выпуск, по счёту уже были операции.** Операционист запрашивает у ОИС выписку с явной датой и временем — не раньше открытия счёта.
- **Выписка — по всем выпускам на счёте.** Тогда отсутствие выпуска в ней означает ноль. Справка по одному выпуску полноту не доказывает.

Документ регистрируется в общем журнале документов ЦД — это сущность [[K21]] «Неизменяемое доказательство»: регистрационный номер, дата и время ([[NR-892-9#1.12]]), сам файл с подписью и его хэш. В карточку счёта или связи документ не кладётся — они хранят только ссылку на запись журнала.

<details markdown="1"><summary>Что хранится и с чем связано</summary>

| Поле | Что это |
|---|---|
| `registration_no`, `registered_at` | регистрационный номер ЦД, дата и время регистрации (п.1.12) |
| `doc_kind` | вид документа — «выписка оператора по счёту N» |
| `content_locator`, `content_hash` | файл с подписью и его хэш — подмена обнаруживается |
| `verification_result` | результат проверки подписи оператора |
| `received_at`, `source_system` | когда и от кого получен |

Одна выписка ОИС связана:

- с внешними срезами [[K12]] — по одной записи на каждый выпуск из выписки, каждая ссылается на документ;
- со связью [[K04]] — если по этой выписке проверялся статус счёта (`last_status_evidence_id`);
- через срезы — с результатами сравнения [[K14]] и запуском сверки [[K13]].

Цепочка: документ ОИС (K21) → срез по выпуску (K12) → результат сравнения (K14) → запуск сверки (K13).

</details>

### Шаг 4. Система запускает первичную сверку
Сравнение уровней — это та же сверка, что и ежедневная: система запускает [[UC-047]] с областью «один выпуск, один счёт N» на момент из выписки ОИС (вид запуска — первичный, при привязке). Правила сравнения, итоги `MATCH` / `MISMATCH` / `UNDETERMINED` и разбор расхождений — там же. Нет документа или в нём нет времени среза — «не определено», а не ноль ([[I07]]).

Является ли первичная сверка сверкой по 282-ФЗ ст.25 с актом и уведомлением Банка России при расхождении — вопрос [[RV-07]]; до ответа юриста — считаем, что является.

### Шаг 5. Готовность связи
**Готовность** — это разрешение принимать зачисления этого выпуска через этот счёт N и сверять его.

- **Всё совпало** — реквизиты совпали с UC-032, первичная сверка дала `MATCH` (остаток подтверждён выпиской по всем выпускам, три уровня равны). Система ставит готовность сама, контролёр не нужен ([[DEC-2026-10-22-02]]).
- **Есть расхождение** — подключается контролёр. Расхождения здесь два:
    - реквизиты счёта не совпадают с уведомлением из UC-032 (И3);
    - у ОИС на счёте уже есть остаток выпуска, а позиций депонентов нет или сумма не сходится (А1).

    Контролёр либо подтверждает готовность после устранения, либо направляет расхождение на разбор в UC-048 «Расследовать расхождение позиций».

### Шаг 6. Система активирует связь
Связь K04 «выпуск ↔ счёт N у оператора» переходит в `READY`. С этого момента по выпуску разрешены зачисления ([[UC-037]]) и ежедневная сверка ([[UC-047]]) через этот счёт N — только для этого выпуска и этого места учёта.

## Альтернативные ветви
- **А1, шаг 4. Первичная сверка: у ОИС уже есть остаток, а позиций нет или сумма не сходится.** Переноса остатков нет ([[UC033-Q1]], закрыт). Количество без основания зачисляется на счёт неустановленных лиц XY; в течение месяца — обладателю по документам, возврат по документу ОИС об ошибке или списание со счёта N по истечении месяца ([[REV-R27]]). Произвольное распределение по депонентам запрещено. После зачисления на XY уровни снова равны, и контролёр может подтвердить готовность.
- **А2, шаг 2. Один счёт N для нескольких выпусков.** Если ОИС ведёт на одном счёте N все выпуски, в ЦД на каждый выпуск своя связь K04: «счёт N + выпуск X», «счёт N + выпуск Y». Каждая проверяется и сверяется отдельно, потому что остатки у ОИС тоже идут по выпускам.
- **А3, шаг 1. Для профиля права выпуска зачисление не включено.** В матрице CD-D-10 для профиля этого выпуска выключено зачисление (MX01 или MX04). Связь можно создать и проверить, но готовность не ставится, пока настройку не включат.
- **А4. ОИС изменила статус или реквизиты счёта.** Узнаём не из среза — срез даёт только остаток. Изменение приходит документом ОИС ([[DEC-2026-10-22-02]]):
    - **по событию** — уведомление оператора с УКЭП, операционист регистрирует его в день получения;
    - **ежедневно** — при каждой сверке UC-047 статус и реквизиты счёта сверяются с документом ОИС, по которому идёт сверка;
    - **раз в месяц** — если ежедневный документ ОИС их не содержит: справка оператора о состоянии счёта на первый рабочий день месяца и перед каждой новой привязкой выпуска.

    Изменение или несовпадение — все связи этого счёта N переходят в `SUSPENDED`. При смене реквизитов создаётся новая версия связи, затем повторная проверка с шага 2.

## Ошибки и неопределённые результаты
- **И1, шаг 2. Конфликтующая связь** ([[C12]]) → «Конфликт», связь не создаётся; ручная замена внешнего ID запрещена.
- **И2, шаг 3–4. Нет подтверждённого остатка** — ОИС не дала выписку или в ней нет времени среза → первичная сверка `UNDETERMINED`, «Ожидает выписки», готовности нет.
- **И3, шаг 5. Реквизиты расходятся с уведомлением UC-032** → контролёр, «Расхождение», готовности нет.

## Переходы

| Состояние связи | Что значит | Когда наступает |
|---|---|---|
| `UNVERIFIED` | связь создана, зачисления запрещены | шаг 2 |
| `READY` | можно принимать зачисления и сверять | шаг 6: проверки пройдены, уровни сошлись |
| `SUSPENDED` | зачисления запрещены, история сохранена | А4: зарегистрировано изменение у ОИС или несовпадение на сверке |
| `READY` повторно | снова разрешено | после повторной проверки с шага 2 |
| версия заменена | старая версия только для истории | смена реквизитов: новая версия создаётся с `UNVERIFIED` |

## Открытые вопросы
- Решено [[DEC-2026-10-22-02]]: готовность без контролёра при совпадении, порядок и периодичность проверки изменений счёта, начальный остаток, перенос остатков.
- Уточнить у ОИС: содержит ли ежедневный документ для сверки статус и реквизиты счёта N; ведёт ли оператор один счёт N на все выпуски.
- Для РЦД: реквизиты читаются методами 1.2–1.4, на каждый раздел — своя версия K04.
