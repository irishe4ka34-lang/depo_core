## Кого идентифицируем
Клиента (депонента), его представителя, выгодоприобретателя и бенефициарного владельца. Идентификацию выполняет компонент онбординга и реестра депонентов, **не учётное ядро**: ядро получает готовый снимок (K01 `party_ref`) и код депонента.

## Сведения о физическом лице {#fl}
| Сведение | Обязательность | Где хранится |
|---|---|---|
| Фамилия, имя, отчество (если иное не следует из закона или национального обычая) | да | реестр депонентов |
| Гражданство | да | реестр депонентов |
| Дата рождения | да | реестр депонентов; входит в код депонента ([[NR-892-2#2.4]]) |
| Реквизиты документа, удостоверяющего личность | да | реестр депонентов; серия и номер паспорта РФ входят в код депонента |
| Документ на право пребывания (проживания) в РФ — для иностранцев и лиц без гражданства | если обязателен | реестр депонентов |
| Адрес места жительства (регистрации) или пребывания | да | реестр депонентов |
| **ИНН** | **да для договоров по цифровым валютам и цифровым правам**, иначе при наличии | реестр депонентов; входит в код депонента |

## Сведения о юридическом лице {#ul}
| Сведение | Обязательность |
|---|---|
| Наименование, организационно-правовая форма | да |
| ИНН или код иностранной организации | да |
| Для российского ЮЛ — ОГРН и адрес | да |
| Для иностранного ЮЛ — регистрационный номер, место регистрации и адрес в государстве регистрации | да |
| Сведения о лицензиях, если деятельность лицензируется | при наличии лицензируемой деятельности |
| Доменное имя и адрес страницы в Интернете, через которые оказываются услуги | при наличии |

Отдельного перечня для ИП в пп.1 нет; для кода депонента ИП 892-П требует дату регистрации в ЕГРИП, ОГРНИП и регистрационный номер в СФР ([[NR-892-2#2.4]]).

## Обновление сведений {#update}

- клиенты низкой степени риска — не реже одного раза в три года;
- остальные — не реже одного раза в год;
- при сомнениях в достоверности — в течение семи рабочих дней.

Изменение сведений, входящих в код депонента, даёт новый код с сохранением прежних ([[NR-892-2#2.11]]).

## Поручение идентификации другой организации {#delegation}
Организация вправе по договору поручить проведение идентификации другой организации (ст.7 п.1.5–1.5-10; перечень допустимых пар «кто поручает — кому» задан по категориям):

- ответственность за соблюдение требований остаётся на поручившей организации (п.1.6);
- исполнитель отвечает за свои нарушения по договору, в том числе неустойкой; нарушение — основание одностороннего отказа (п.1.7–1.8);
- исполнитель передаёт полные сведения не позднее трёх рабочих дней (п.1.9).

**Для нас:** вправе ли цифровой депозитарий поручить идентификацию брокеру — открытый вопрос ACC-Q2. До ответа ЦД идентифицирует клиентов сам, сведения брокера принимаются как документы.

## Проверка по перечням {#lists}

- проверять клиентов на наличие в перечнях лиц, к которым применяются меры замораживания, — не реже раза в три месяца (пп.7);
- применять меры замораживания — незамедлительно, не позднее 24 часов с публикации перечня (пп.6). Для ядра это ограничение по счетам (UC-042).

## Что это значит для ядра

- Ядро не хранит персональные данные и не проводит идентификацию.
- Ядро требует, чтобы у депонента был код по [[NR-892-2#2.4]] и признак «идентификация пройдена» с датой; без этого счёт не открывается ([[REV-R18]]).
- Повышенная степень риска по итогам идентификации — случай контролёра ([[REV-R22]]).
- Срок следующего обновления и реакция на просрочку — [[REV-R26]].
