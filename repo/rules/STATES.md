Коды — справочник CD-D-11; у разных объектов свои наборы кодов. Полные условия переходов — [[MODEL-Q05]].

## Счёт {#account}

**Переходы.** `OPEN → SUSPENDED → OPEN`; `OPEN → CLOSED`

- Статусы реестра счетов по 892-П: открыт, операции приостановлены, операции возобновлены, закрыт — с датой и временем ([[NR-892-4#4.2]]). Возобновление — переход `SUSPENDED → OPEN` с отдельной записью.
- Каждый переход — по подтверждённому основанию и проверке полномочия, с записью «до/после» в аудите и записью реестра операций ([[NR-892-5#5.5]]).
- Закрытие — только при нулевом остатке по всем позициям счёта ([[NR-892-8#8.4]]); владельцу — уведомление не позднее следующего дня ([[NR-892-9#9.2]]). Сценария закрытия в основной цепочке пока нет — [[RV-05]].

## Связь со счётом N {#custody_link}

**Переходы.** `UNVERIFIED → READY → SUSPENDED → READY`; при смене реквизитов — новая версия с `UNVERIFIED`, старая помечается заменённой

- Связь — запись «выпуск X учитывается на нашем счёте N у оператора Y». `UNVERIFIED` — создана, зачисления запрещены.
- `READY` — реквизиты совпали с UC-032, остаток подтверждён выпиской ОИС, три уровня равны. При полном совпадении ставится автоматически, при расхождении — контролёром ([[DEC-2026-10-22-02]]). Это готовность связи, а не зачисление.
- Остаток без основания — на счёт неустановленных лиц ([[REV-R27]]); готовность ставится после того, как уровни сошлись.
- Изменение статуса или реквизитов у ОИС (уведомление, ежедневная сверка, ежемесячная справка) — `SUSPENDED` до повторной проверки; операции, проведённые при прежней версии, ссылаются на неё.

## Внешнее событие {#external_event}

**Переходы.** `RECEIVED → VALIDATED → PROCESSED`; `RECEIVED → QUARANTINED`

Проверяются подлинность, схема, сопоставление и однократность. `PROCESSED` — результат обработки сохранён; проводка при этом не обязательна.

## Учётная операция {#accounting_operation}

**Переходы.** создаётся сразу в `POSTED`

Создаётся только полностью проведённый результат; ожидание отражается в команде K18 и событии K10. Частично проведённой операции нет.

## Внешняя операция {#external_operation}

**Переходы.** `PENDING → CONFIRMED / REJECTED / UNKNOWN`; `UNKNOWN → CONFIRMED / REJECTED`; для заявления на открытие счёта N — до передачи `DRAFT → PREPARED → PENDING`

- Конечный исход — только по достаточному подтверждению; `UNKNOWN` становится конечным только после выяснения ([[I05]]).
- Заявление на открытие счёта N ([[UC-032]]): `DRAFT` — черновик, передача недоступна без зарегистрированного основания; `PREPARED` — основание есть, дублей нет; `PENDING` — передано, комплект зарегистрирован; `CONFIRMED` — только по подписанному уведомлению оператора ([[DEC-2026-10-22-01]]).
- Для ручного открытия счёта N неизвестный исход не даёт оснований подать новое заявление; выясняется по документам, без автоматического опроса.

## Команда {#command_receipt}

**Переходы.** `RECEIVED → IN_PROGRESS → SUCCEEDED / FAILED / UNKNOWN`

`FAILED` — доказанный отказ без эффекта; неопределённость `FAILED` не обозначается. Повтор возвращает прежний результат ([[I04]]).

## Сверка {#reconciliation_run}

**Переходы.** запуск `STARTED → COMPLETE / INCOMPLETE`; строка `MATCH / MISMATCH / UNDETERMINED`

`MATCH` — только при полном сопоставимом срезе и нулевых разницах ([[C06]]). Новый запуск прежний не перезаписывает.

## Выписка {#statement}

**Переходы.** `BUILDING → ISSUED / FAILED`

`ISSUED` — только после сохранения строк, файла с хэшем и параметров расчёта. Исправленный экземпляр — новый ([[I08]]).

## Дело расхождения {#discrepancy_case}

**Переходы.** `OPEN → INVESTIGATING → CLOSED`

`CLOSED` — только после повторной сверки с `MATCH`, решения второго сотрудника и доказательств ([[R-009]], [[R-006]]).

## Резерв {#reservation}

**Переходы.** `ACTIVE → CONSUMED / RELEASED` (цель — профиль РЦД)

Только по доказанному исходу поручения; по тайм-ауту резерв не снимается.
